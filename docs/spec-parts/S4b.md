The original answers every query in this section with SQL over a SQLite
database. Under `br --no-db` that database is an ephemeral store loaded from
`.beads/issues.jsonl` at start-up (`src/storage/sqlite.rs:2694` notes the
ephemeral file is a uniquely named temp file, never `:memory:`), so every
SQL-specific semantic below — `LIKE` folding, `COLLATE NOCASE`, `NULL`
handling, `instr(lower(…))`, text comparison of timestamps — reaches the
output bytes and is part of the contract. Each clause states the relation
behaviorally; no clause requires the port to use SQL.

### The BLOCKED relation

The relation maps an issue id to a list of *blocker refs*. It is the single
source of truth for `blocked`, for `ready`'s exclusion, for `stats`'
blocked/ready counts, and for the claim and close guards. It is rebuilt from
the dependency graph on every read (under `--no-db` the cached projection is
always stale at start-up, so the compute path below is the one the goldens
exercise).

**Numerics → S7.** `priority` is a small signed integer confined to `0..=4` by every parser (S4.107, S4.108). Counts (`total`, `count`, `blocked_by_count`, group counts, `total_children`) are unsigned machine words; the corpus reaches 8. The epic percentage is an integer truncating division computed in 128-bit width (S4.191). The average lead time is the only floating-point figure: whole-hour integers (a truncating conversion from a duration, S4.154) summed and divided by the count; the corpus reaches 2.0 and 558.0 hours, and the 558.0/24 = 23.25 case lands exactly on a ties-to-even boundary when printed to one decimal (`23.2`, not `23.3`) — S5 owns the printing, S7 owns the fact that the value is exact in binary.

**Effects → S8.** Every command in this section is read-only: it reads `.beads/issues.jsonl` (and `.beads/policy.yaml` for the ready status group and the custom-status vocabulary, and `.beads/last-touched` when `show` has no positional id), reads the wall clock once (S4.113), and writes only stdout/stderr. The stale blocked-cache projection is recomputed in memory and never persisted on a read path. Whether a read-only command ever creates a file under `.beads/` is OQ-008.

**Oddities → S10.** (1) `list --fields` is silently ignored outside CSV (S4.134). (2) `list --deferred` reads as "only deferred" but is a no-op on the default corpus (S4.131). (3) `count`'s default corpus hides deferred issues while `list`'s shows them (S4.144). (4) `--title-contains` and `search` fold ASCII case only, while `--desc-contains`/`--notes-contains` fold Unicode case (S4.109, S4.129, S4.137). (5) `search -p 0-1` is an error while `list -p 0-1` is accepted — `search` parses each `--priority` value as a single priority with no ranges or comma lists (S4.140). (6) The `blocked` text line says `open dependencies` even for one blocker and even when the blocker ref is a `:parent-blocked` or `:child-open` rollup rather than a dependency. (7) `stats` counts templates and every custom-status issue in `total_issues` but in none of the per-status counters (S4.151). (8) `ready`'s hybrid default can list a P3 above a P2 (S4.174). (9) `--blocking-only` on `dep cycles` changes nothing (S4.186).

**Data model → S3.** Fields this section reads: `id`, `title`, `description`, `notes`, `status`, `priority`, `issue_type`, `assignee`, `created_at`, `updated_at`, `closed_at`, `defer_until`, `due_at`, `ephemeral`, `pinned`, `is_template`, `labels`, `dependencies` (`issue_id`, `depends_on_id`, `type`), `comments` (`id`, `author`, `text`, `created_at`). Absent booleans (`ephemeral`, `pinned`, `is_template`) behave as false everywhere. Absent optional strings never match a containment filter. A dependency target that is not a stored issue is legal and carries the synthetic status `unknown` in a blocker ref (S4.157). `search`'s corpus includes comment text, so comments are part of the queryable surface.
