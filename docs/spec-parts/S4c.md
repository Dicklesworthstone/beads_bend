Reading key for the `cases` column: a bare name is a row of `goldens/cases.tsv`;
`(case to add: …)` marks a behavior established by running the original through
`scripts/ws-run.sh --oracle br --no-db ::` (pinned instant `2026-01-02 03:04:05` UTC,
workspace `/mnt/proj`, `USER=tester`) for which no captured case exists yet.

**How the goldens show a store change.** `scripts/ws_inner.py` hashes `.beads/issues.jsonl`
and `.beads/last-touched` before and after the run and appends `--- .beads/issues.jsonl ---`
/ `--- .beads/last-touched ---` plus the file's bytes to stdout **only when that file's
sha256 changed** (`scripts/ws_inner.py:dump_changes`). Therefore "no dump" in a golden
means *the file's bytes are identical to the fixture's*, which a port satisfies either by
not writing or by writing identical bytes. Every clause below that says "the store is not
rewritten" means exactly that observable.

## Handover notes

**To S6 (order).**
- Store line order after every mutation is ascending byte order of `id` (S4.206); hierarchical ids sort as plain strings, so `proj-uly.1.1` precedes `proj-uly.2`.
- Multi-id `update`/`close` emit their per-id output blocks in command-line order; `reopen`/`undefer`/`defer` emit all successes before all skips (S4.314, S4.327).
- `label add`/`label remove` iterate labels in the outer loop and issues in the inner loop (S4.370).
- `delete` sorts its id set ascending BEFORE resolution and again before tombstoning, so the command-line order never reaches the output; the `--cascade` edge-removal pass iterates a hash set in unspecified order, but that pass produces no ordered output (S4.335, S4.340).
- The `dependencies` array of a record created with several `--deps` is re-ordered by the export, not by the command (S4.229).
- `dep cycles` is the only surface that prints an actual cycle witness; `dep add` never does (S4.355).
- The ambiguous-id candidate list is hash-random in the original and is canonicalized to byte order by `scripts/ws_inner.py` (DISC-005) — S4.275.

**To S7 (numerics).**
- `priority` is an integer 0–4 inclusive; out-of-range is refused (S4.239). Default `2`.
- `estimated_minutes` is a signed 32-bit integer; negatives are refused (`cannot be negative`) and values above `525960` are refused (`exceeds maximum (525960 minutes / ~1 year)`).
- `TITLE_MAX_CHARS` = **500**, counted in Unicode scalars, not bytes (S4.222).
- Label length limit = **50** bytes; `external_ref` limit = **200** bytes with no whitespace allowed.
- `ISSUE_LABEL_MAX_COUNT` = **64** (`src/validation/mod.rs:24`); exceeding it gives `exceeds 64 labels`. The corpus never reaches it.
- `comments add -f` / `-f -` caps its input at **10485760** bytes (10 MiB) and requires valid UTF-8 (S4.381).
- A bare date given to `--until`, `--due` or `--defer` resolves to **09:00:00 local time** of that day, not midnight; the keyword `today` resolves to **17:00:00 local time** (S4.322). Under `TZ=UTC` local equals UTC.
- The cap on `create -f` bulk import and on `delete --from-file` input sizes is unmeasured.
- `compaction_level` and `original_size` default to `0` on every created record; `--dry-run --json` omits `original_size` (S4.235).
- Comment ids are a monotone integer sequence over the whole store, `max + 1` (S4.382).
- `close` reports `closed_at` with a `+00:00` offset in JSON while the store writes `Z` (S4.298); `defer` does the same for `defer_until` (S4.322).
- The cycle search is depth-bounded (`DEPENDENCY_TRAVERSAL_MAX_DEPTH`, `src/storage/sqlite.rs:6976`); beyond that depth a cycle is not reported.

**To S8 (effects).**
- Files written by this surface: `.beads/issues.jsonl` (one full rewrite per invocation, only when something is dirty — S4.202, S4.203) and `.beads/last-touched` (S4.207–S4.211).
- `.beads/last-touched` is created with mode `0600`, truncated, written best-effort (a failure never changes the exit code), and holds `<id>\n`.
- `delete` never creates `last-touched`; it removes the file when the stored id was deleted (S4.210).
- `label rename` writes the store but not `last-touched` (S4.211).
- `create --ephemeral` writes `last-touched` but not the store (S4.234).
- `create --dry-run`, `delete --dry-run` and `epic close-eligible --dry-run` write nothing at all (S4.235, S4.338, S4.393).
- Reads: `--description-file <path>` and `comments add -f <path>` read a file (or stdin for `-`) exactly once, before any mutation; `create -f`, `delete --from-file`, `--agent-context @path` likewise (S4.225, S4.237, S4.340).
- Clock: every mutating command reads the wall clock once per issue update for `updated_at`/`closed_at`/`deleted_at`/`created_at`; in a pinned run all of them equal the pinned instant.
- Environment read on this surface: `USER`, plus `BD_ACTOR`, `BEADS_ACTOR`, `LOGNAME`, `USERNAME` for the comment-author ladder, plus `BR_AGENT_NAME`, `BR_HARNESS`, `BR_MODEL` (recorded on events only, never in the JSONL — S4.214).
- Excluded effects observed in the source but not on this surface: `.br_history/` backups, the lock files, `close_metadata`, `policy.yaml` gates.

**To S10 (oddities, reproduce, do not fix).**
- `update --status <same value>` bumps `updated_at` and rewrites the store, while `-p <same value>` does not (S4.262 vs S4.264).
- `close` exits **3** on a partially applied batch although it did write the closures (S4.294) — the only non-zero exit with a rewritten store.
- `reopen` has no `NOTHING_TO_DO`: an all-skipped reopen exits **0** while an all-skipped close exits **3** (S4.313 vs S4.293).
- `delete` with dependents and no flag is a silent preview that exits **0** (S4.333).
- `references_updated` is always `0`; `labels_removed`/`events_removed` are always `0` for a soft delete even when the issue has labels (S4.336).
- `create --dry-run --json` omits `original_size` although a real create emits it (S4.235).
- `create --deps` accepts `blocked-by` and lists it in its error text; `dep add --type` does not (S4.229 vs S4.352).
- `q` writes no `source_repo`/`source_repo_path`, so its records end up with `"source_repo":"."` while `create`'s carry the directory basename (S4.251).
- `dep add`/`dep remove` write `last-touched` even when they changed nothing (S4.209, S4.358, S4.360).
- `close` prints `closed_at` with `+00:00` in JSON but writes `Z` to the store (S4.298).
- `create --status tombstone` produces a tombstone without `delete_reason` or `original_type`, unlike `delete` (S4.231 vs S4.330).
- `epic close-eligible` writes `close_reason` `All children completed` while `close` without `--reason` writes `done` — two different defaults for the same field (S4.391 vs S4.291).
- `defer` WITHOUT `--until` clears an existing `defer_until` rather than leaving it alone (S4.323).
- `label remove` of an absent label prints the SUCCESS glyph `✓` on stdout, while `dep remove` of an absent edge prints `Warning:` on stderr (S4.375 vs S4.360).
- `epic close-eligible --dry-run` prints `Would close 0 epic(s):` where the non-dry run prints `No epics eligible for closure` (S4.392 vs S4.393).
- `label add`'s positional split makes the LAST positional a label even when it is id-shaped (S4.370).

**To S3 (data model).**
- Fields this surface writes and their exact JSON key order as the store shows them: `id`, `title`, `description`, `acceptance_criteria`, `status`, `priority`, `issue_type`, `assignee`, `owner`, `estimated_minutes`, `created_at`, `created_by`, `updated_at`, `closed_at`, `close_reason`, `closed_by_session`, `due_at`, `defer_until`, `external_ref`, `source_repo`, `source_repo_path`, `deleted_at`, `deleted_by`, `delete_reason`, `original_type`, `compaction_level`, `original_size`, `notes`, `labels`, `dependencies`, `comments`, `ephemeral`.

- Comment record: `id`, `issue_id`, `author`, `text`, `created_at` — S4.380.

- `status` reaches the values `open`, `in_progress`, `closed`, `deferred`, `tombstone` on this surface; `blocked`, `draft` and `pinned` appear only in skip messages.
