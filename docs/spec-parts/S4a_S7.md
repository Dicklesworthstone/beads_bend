| S4.8 | The hash **length is adaptive** in the issue count. Lengths are tried in ascending order from `min_hash_length` 3 through `max_hash_length` 8. ## Handover notes

- **S6 (order):** the substring-match candidate list is produced in ascending id order by the store's own `ORDER BY id` over a TEXT column (byte order), and the harness sorts it again — the two agree, but the underlying order is the store's. See S4.44 and DISC-005.
- **S6 (order):** `parse_priority_filter` returns its selection through an ordered set, so filter values are always ascending and de-duplicated regardless of the order typed (S4.67).
- **S6 (order):** labels collected at `create` keep first-occurrence order in memory, while the JSONL write-back sorts and de-duplicates them (`edge_precision_rewrite` shows `["alpha","zeta"]`). The write-back rule belongs to S5.
- **S5 (outputs):** the exact plain-text shapes quoted here (`✓ Created <id>: <title>`, `Dry run: would create issue <id>`, `  Avg Lead Time:          2.0 hours`, the `Error:`/`Hint:` pair) are cited only as evidence for the algorithm; their column widths, glyphs and trailing newlines are S5's to pin.
- **S5 (outputs):** the `defer` JSON payload's `+00:00` offset spelling versus the store's `Z` (S4.64) is a rendering split worth an S5 clause of its own.
- **S3 (data model):** `content_hash` is present on the record type but skipped by its JSON representation (S4.51); the model section owns that field's existence, this section owns its arithmetic.
- **S3 (data model):** `original_size` is declared as an optional signed 32-bit field yet appears as `0` on every exported record, so the loader materializes it — that materialization is S2/S5's.
- **S8 (effects):** the clock is read once per create attempt (S4.52) and again on each of the up-to-ten insert retries (S4.14); the retry path also sleeps 10, 20, … milliseconds, which is unreachable in `--no-db`.
- **S8 (effects):** `--no-db` rebuilds the child-counter table from the file on every invocation (S4.25); that rebuild is an effect of the load, not of `create`.
- **S9 (errors):** every error string quoted here carries its stream and exit code inline; S9 owns the full table.
- **S10 (oddities):** a non-numeric priority is reported **uppercased** (`-p x` → `got: X`) because the uppercase precedes the parse (S4.66). Reproduce, do not fix.
- **S10 (oddities):** a filter token such as `-1` splits at its first `-` into an empty left part and therefore falls through the range branch to the single-value branch, where it is reported as `-1` (S4.67).
- **S10 (oddities):** id lookup lowercases with full Unicode rules, not ASCII rules (S4.36), so a non-ASCII uppercase input can change byte length before the lookup.
- **S10 (oddities):** the id seed measures fields in bytes while the title limit measures in characters (S7.1 versus S4.75) — a 500-character CJK title is 1500 seed bytes and still valid.
- **S10 / DISC-005:** the ambiguous-candidate order is canonicalized by the harness (S4.44).
