## S6. Order-leak inventory

Every place where an iteration or insertion order reaches an output on an
in-scope `--no-db` path.

**Determinism evidence.** `scripts/floor.sh --repeat 3` found exactly one
unstable case among the 231 captured cases (`show_partial_ambiguous`,
DISC-005). In addition, this extraction ran the oracle 5–8 times per probe
through `scripts/ws-run.sh --oracle` over outputs the corpus does not exercise
— `count --by-label/--by-assignee/--by-type/--by-status/--by-priority` (plain
and `--json`), `label list-all` (plain and `--json`), `stats` (plain and
`--json`), `blocked` (plain and `--json`), `dep cycles` (plain and `--json`),
`epic status --json`, `epic close-eligible`, `dep tree … --json`,
`dep list … --json`, `ready --json`, `list --json`, `search … --json`,
`close … --json`, `update … --claim`, `delete … --cascade --json`,
`close … --suggest-next --json`, `label rename … --json`,
`update … --set-labels z,a,m,b --json`, `create … -l zeta,alpha,mid,beta --json`,
`show <target with 18 tied dependent edges>` — plus the same probe set against a
24-issue store and a 20-issue synthetic store built inside the sandbox. Every
one of them was byte-identical across repeats. The single hash-random leak in
`--no-db` mode remains the ambiguous-partial-id candidate list (S6.31).
